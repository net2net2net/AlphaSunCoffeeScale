# CoffeeScale · 产品结构规划 —— 四模块模式（专业模式 / 新手模式 / 简易计算器 / 手冲大师方案）

> 状态：规划稿（2026-09-09）。定位原则（用户确认）：**目前程序全部功能即「专业模式」**；
> 程序将进一步改进，新增「手冲咖啡软件入口界面」，下设 **新手模式 · 专业模式 · 简易计算器 · 手冲大师方案** 四块功能，
> 其中 **专业模式进入目前程序界面**（不动现状，仅作为四模块之一被入口承载）。
> 本文是架构与实施蓝图，供后续迭代直接执行；与《01-总览》《02-计算逻辑》配套。

## 1. 产品形态总览

```
┌────────────────────────── 启动入口 Home（新增）──────────────────────────┐
│  手冲咖啡 · CoffeeScale                    （顶栏：应用名/作者/语言）      │
│                                                                            │
│   ┌────────────┐  ┌────────────┐  ┌────────────┐  ┌────────────┐          │
│   │ 新手模式    │  │ 专业模式 ★ │  │ 简易计算器  │  │手冲大师方案 │          │
│   │ 引导式上手  │  │ 现有全功能  │  │ 快速换算    │  │ 方案库/大师 │          │
│   │ Beginner   │  │ Professional│  │ Calculator  │  │ Master Plan│          │
│   └────────────┘  └────────────┘  └────────────┘  └────────────┘          │
│   四卡 + 一行副标题说明；记忆上次所选模式，下次直达                            │
└────────────────────────────────────────────────────────────────────────────┘
```

- 四模块共享同一套 **Core 引擎 / BrewViewModel 领域逻辑 / I18n / 本地存储（settings·brews·myplans）**，
  差异只在「UI 复杂度与引导深度」——避免逻辑分叉、单事实来源（Single Source of Truth）原则不变。
- 四端（Win/Android/iOS/Mac）行为一致：入口为第一个页面；桌面也受益（同一程序四模式）。

## 2. 四模块定义

| 模块 | 一句话定位 | 目标用户 | 界面复杂度 | 与引擎关系 |
|---|---|---|---|---|
| **专业模式**（现程序） | 全参数、全流程的冲煮方案＋实时冲煮称 | 进阶/竞赛向玩家 | 高（双栏/分页） | ComputeRecipe 全量 + 实时状态机 |
| **新手模式**（新增） | 引导式冲煮：答 3–5 个问题 → 得到可直接照做的方案 | 第一次手冲 | 低（问答向导＋大字步骤） | 引擎子集 + 问题→参数映射 |
| **简易计算器**（新增） | 快速换算：粉量/粉水比/水量/闷蒸/水温 即算即得 | 日常速查 | 极低（两块输入＋大结果卡） | ComputeRecipe（极简参数面） |
| **手冲大师方案**（新增聚合） | 大师方案库＋我的方案＋历史冲煮记录＋分享/导出 | 想复刻好配方 | 中（列表＋详情＋应用） | MasterPlanItem/MyPlan/记录回灌引擎 |

> 「简易计算器」与「新手模式」命名/形态可再议（例如：简易计算器=原"一键生成"的极简态；
> 手冲大师方案=现推荐页/大师清单/我的方案/记录四个入口的聚合升级）。

## 3. 各模块需求与复用明细

### 3.1 专业模式（现状即交付，零重构）

- 入口直达**当前 MainWindow 界面**（设置＋实时冲煮/推荐、记录、方案导入导出、语言切换全保留）。
- 改动建议仅两处轻量接入：
  1. 顶栏加「← 模式」返回（Home）；桌面可 Esc/按钮返回；
  2. 可选：接收来自其他三模块的「预填参数包」并直接生成方案（对外统一为 `RecipeOptions`，天然支持）。

### 3.2 新手模式（建议 Phase 顺序中后置，依赖向导组件）

核心：**把专业参数翻译成日常问题**，一条「问题 → 参数映射」链路（待实现于 VM 或 Core 新类 `BeginnerWizard`，保持框架无关）：

| 向导问题（示意） | 选项 | → 引擎参数 |
|---|---|---|
| 你想要什么口感？ | 清爽酸香 / 均衡 / 醇厚甜感 | flavor=acidic / balanced / sweet |
| 咖啡豆烘得怎样？ | 浅(水果酸香) / 中(均衡) / 深(醇苦) | roast=ultra_light / medium / ultra_dark（或给 Ag 区间图示） |
| 几个人喝？ | 1 杯(15g) / 2 杯(25g) | size=standard / large；dose=15 / 25 |
| 有什么器具？ | 锥形滤杯 / 蛋糕杯 / 聪明杯 / 不知道 | dripper=v60 / wave / smart（"不知道"默认 v60） |
| 你磨好粉了吗（研磨？） | 我没有磨豆机（买粉） | 提示按 C40/EK 刻度让店家磨（读研磨推荐档） |

- 之后**一键「生成我的第一壶」**：用引擎默认（处理法=水洗、滤纸=漂白等）跑 ComputeRecipe，
  展示为**大字分步卡片**：①称粉 ②润湿滤纸 ③注水闷蒸 X 秒 ④分段注到 N g ⑤滴滤至完成——只显示当前步。
- 术语通俗化：所有专业词给「大白话」副标题（复用 I18n，不新造文案源）。
- 深度可逐步增加：内置 2–3 个「经典新手配方」模板兜底（无脑照做）。

### 3.3 简易计算器（建议最先落地——见效快、复用现引擎）

- UI：两卡输入 → **粉量(g)** 与 **粉水比(1:N)**（默认 15g / 15，滑块＋数字），
  可选折叠「高级」：烘焙度（粗分浅/中/深三档）＋滤杯（用于出研磨/水温）。
- 输出大卡（只读、即时更新）：总水量 g、粉水比、**建议水温℃、闷蒸 s、注水 3 段目标 g**（如总水量>粉量×2.5 时按三段）、
  研磨档（C40≈/EK≈）、预计时间；一键「在专业模式打开」→ 带参跳转。
- 实现 = 包一层极薄 VM（`CalculatorViewModel`）调用同一 `ComputeRecipe`（内部缺省参数走默认档），**不新写任何算法**。

### 3.4 手冲大师方案（聚合升级，建议依赖方案数据通路已有能力）

- 三个数据源统一视图：
  1. **大师方案清单**（内置/可搜索，现有 ShowMasterPlanPicker 升级为独立页）；
  2. **我的方案**（收藏/自定义，myplans.json，现有功能抽取）；
  3. **历史冲煮记录**（brews.json 列表 + 「复刻为方案」入口，现有 KeyByLabel 反查已具备）。
- 每项可：查看详情（正文＋结构化参数）、应用（回灌引擎 → 生成方案 → 可跳专业模式实施）、
  收藏/删除、**分享文本复制/导入**、**导出 CSV**（记录）。
- 与「新手/简易」互为补充：大师方案详情里对新手展示「这壶豆怎么买/怎么磨」的直白提示。

## 4. 技术架构建议（代码层）

1. **模式路由**：新增 `AppMode` 枚举（Home/Professional/Beginner/Calculator/MasterPlan）＋ UI 层 `MainWindow`
   顶部一个 `Border` 页面容器切换（复用现有 PresentModal 的思路但用页面级切换，不做多 Window——移动端不允许二级 Window）。
2. **入口 Home**：新增构建方法 `BuildHome()`（四卡 Grid/StackPanel，响应式：横屏四列/竖屏 2×2 或列表），
   顶栏语言/作者沿用现有 header；模式记忆写入 `BrewSettings.Mode`（默认 Home；可设"记住上次=直达"选项）。
3. **子页面容器化**：把专业模式当前内容包成可挂载视图（现状 MainWindow 已全 C# 构建，抽取成本低）：
   建议把 `BuildSettings/BuildBrew/BuildRecommend/BuildLeft/...` 归入内部子视图组，由模式路由决定可见性。
4. **跨模块参数包**：统一 `RecipeOptions`（已有）作为「简易/新手/大师 → 专业」的唯一入参格式；新增
   `BeginnerWizard.Questions → RecipeOptions`（Core 层新类，可单测）。
5. **测试**：Core/VM 增加 BeginnerWizard 映射测试、CalculatorViewModel 换算测试；UI headless 增加
   Home 四卡存在性、模式切换、返回链测试；全量回归 152+ 用例全绿为门槛。
6. **I18n**：新文案按现有 key 约定扩充（Mode_Professional/Beginner/Calculator/MasterPlan…），语言切换仍走 RebuildAllText。

## 5. 落地阶段建议（Phase 16+，可与真机验证穿插）

| 阶段 | 内容 | 验收 |
|---|---|---|
| Phase 16 | 模式骨架：AppMode＋Home 四卡＋模式记忆＋专业模式挂载与返回 | 桌面+Android 均可进 Home→专业→返回；152 用例 + 新增 headless 全绿 |
| Phase 17 | 简易计算器（首功能落地） | 输入粉量/粉水比即出水量等；一键跳专业生成；单测覆盖 |
| Phase 18 | 新手模式向导（问题→方案→大字步骤） | 首次用户不看说明能完成一壶；向导映射单测 |
| Phase 19 | 手冲大师方案聚合页（大师/我的/记录三源一体） | 应用/收藏/分享/CSV 全通；回归 |
| Phase 20 | 打磨：桌面/平板/手机直板与横屏四模式排版、真机验证、打包发布 | dist 更新（apk/exe/zip） |

每阶段结束出 dist 交付物并真机确认（沿用：不用模拟器像素校验）。

## 6. 需阳光拍板的开放问题

1. **默认入口**：打开程序默认进「模式首页」，还是保持「直达专业模式、从设置里进其他模式」？（影响 Phase 16）
2. **简易计算器的"高级折叠"里烘焙度用 3 档粗分还是 10 档？**（建议首页 3 档粗分，展开后可精确到 10 档）
3. **新手模式问题数**：3–5 个问题哪几个必问（口感/烘焙/粉量/器具 建议 4 个起步）。
4. **手冲大师方案是否含"在线下载/同步大师方案包"**（现为内置清单，联网拉取属后续可选项）。
5. **烘焙度档位体系**（10 档 vs 8 级 SCAA）与默认档位命名——见《01-总览》差异 #1–#3，定稿后再铺开四模块 UI 档位文案。
6. **模式首页是否需要品牌化视觉**（图标/卡片配色），还是沿用现有咖啡色系极简卡片即可。
