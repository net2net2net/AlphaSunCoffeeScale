## 1. 工程总览（四层解耦架构）

一套 C# 代码原生编译到 **Windows / Android / iOS / MacCatalyst**（.NET 9 + Avalonia 11.2.5，无 XAML、纯 C# 构建 UI）。

| 工程 | 作用 | 规模（行） | 关键约束 |
|---|---|---|---|
| `src/CoffeeScale.Core` | 冲煮逻辑引擎（纯逻辑、零 UI 依赖） | ~2,200 | 含烘焙度档位/处理法/滤杯/滤纸/研磨/水质/方法档案、配方构建、黄金杯、阶段状态机、养豆推荐、仓储（设置/记录/我的方案） |
| `src/CoffeeScale.ViewModels` | BrewViewModel（框架无关，Marshal 委托回写 UI 线程） | ~1,400 | 驱动生成配方、模拟注水、保存记录、方案导入导出、语言切换 |
| `src/CoffeeScale.UI` | 共享 UI 控件库（四端复用） | ~2,300 | `App` / `MainWindow` / `Converters`；桌面编译为 Window，Android 编译为 UserControl（单视图） |
| `src/CoffeeScale.Avalonia` | 桌面 head（Windows WinExe 单文件） | 小 | `Program.cs` 三层异常兜底 + 崩溃弹窗 + crash.log |
| `src/CoffeeScale.Android` | Android head（MainActivity） | 小 | Debug APK 产出 |
| `src/CoffeeScale.iOS` / `.MacCatalyst` | 苹果端 head | 小 | 代码就绪（本机未实机验证） |
| `tests/*` | Core / VM / UI 三层测试 | ~3,300 | **152 用例全绿**（Core 73 + VM 50 + UI 29，README 亦载 152） |

工程文件：`CoffeeScale.sln`；桌面发布脚本 `publish-android.ps1`、构建环境修复 `dotnet-env.sh`、图标生成 `tools/make_icon.py`。

## 2. 功能全貌（截至 2026-09-09）

- **参数域**：粉量档位（少/标准/大 3 档）＋粉量、粉水比、**烘焙度 10 档（Agtron 粉样标尺）＋烘焙值 Ag 输入**、
  风味走向（3）、处理方式（8）、滤杯（8）、滤纸/滤网（6）、研磨度（推荐 5 档）、水质推荐（4）、
  冲煮方法（10，含 SCA 杯测）、产地（18＋兜底）、豆种（14＋兜底）、豆密度（3）、养豆期/烘焙日期、冲煮日期。
- **推荐输出**：总水量、推荐水温、闷蒸秒、研磨度（档位＋C40/EK 刻度）、建议流速、注水阶段路线图、预计时长、
  水质（TDS/GH/KH）、养豆四态＋养豆期满日期、黄金杯诊断（EY/TDS）＋自动校准说明。
- **实时冲煮**：计时/重量/流速/实际粉水比/阶段与总体进度/偏快与停滞警告；杯测法静态计时模式；前进/后退阶段。
- **数据**：`brews.json` 冲煮记录（增删、CSV 导出）、`myplans.json` 我的方案（收藏/去重覆盖/删除）、
  `settings.json` 参数与语言偏好自动恢复、方案便携分享文本（`CoffeeScalePlan v1`，可复制/导入）。
- **交互**：中英双语（I18n）、模拟器/真机自适应布局（竖屏左右滑动分页 / 横屏双栏）、模态浮层（移动端）。

> 详情逐条见 README「功能」与 `02-咖啡计算逻辑说明.md`。

## 6. 本机构建与发布（验证有效）

```bash
# 编译（0 警告 0 错误）
dotnet build -c Release -r win-x64

# 桌面单文件发布（跳过 android TFM 防 NU1102）
dotnet publish -c Release -r win-x64 -p:CoffeeSkipAndroid=true -o dist/win-x64

# Android APK：镜像到英文路径再打（aapt2 非 ASCII bug 规避）
#   robocopy <仓库> C:\dev\cs-build /MIR /XD bin obj .git
#   偶发 XABLD7000/AVLN9999 → rm -rf UI 与 Android 的 bin+obj Debug/net9.0-android 后重打
dotnet build src/CoffeeScale.Android/CoffeeScale.Android.csproj -t:SignAndroidPackage -c Debug -f net9.0-android

# 全量测试
dotnet test
```

⚠️ 环境坑速查（详见 README「本环境踩坑」与各日日志）：
1. 沙箱开启会拒写部分 NuGet 原生资产 → 构建需放行沙箱或 `-r win-x64` 只还原 Windows 资产。
2. 本机 shell 缺系统环境变量会致 NuGet path1=null → 用 `dotnet-env.sh` 注入。
3. 后台任务默认 120s 会被掐断 → dotnet 长任务显式给 ≥600s 超时。
4. 大 zip 覆盖/删除触发安全钩子 → 先 `rm -f` 旧包再 `Compress-Archive` 到新路径。

## 7. 差异与待确认（盘点发现，请阳光裁决）

| # | 差异 | 证据 | 建议 |
|---|---|---|---|
| 1 | **烘焙度档位数**：代码为 **10 档**（blonde 110–120 … extreme_dark 20–30，含超浅烘/极浅烘/肉桂烘新名）；README 与用户级约定记为 **8 级 SCAA 粉样 10 分带**（Very Light 90–100 … Very Dark 20–30） | `BrewEngine.RoastProfiles` 10 项 vs README L30 8 级 vs 用户约定 | 确认最终档位体系与命名；若定 8 级需回改代码与档位表，若定 10 级需同步 README/约定与 Ag 分区展示 |
| 2 | **默认档位 key 与显示名**：`BrewSettings` 默认 `Roast="light"`（Ag 80–90，代码 Label「肉桂烘」）但注释写「默认浅烘 Light」，而 key `ultra_light`（Ag 90–100）Label 恰为「浅烘」 | Settings.cs L14–15 vs BrewEngine.cs L169–170 | 复核默认烘焙度 = 哪个 key/Ag，避免「浅烘」指代漂移 |
| 3 | **UI 显示名来源**：档位下拉走 `I18n Roast_<key>`，而引擎 `Label`（中文）另有一套 → 同一档在设置区与报告/记录可能出现两种名称 | MainWindow Combo 用 I18n 键 vs Recipe.RoastLabel=Label | 统一「一个档位一个权威名」，I18n 与 Label 由单一来源生成 |
| 4 | README「Core 72」与 `wc -l` 标称、实际 xUnit 计数存在 72/73 出入 | README L62 记 72，README 架构表记 73 | 以 `dotnet test` 实际输出为准更新 README |
